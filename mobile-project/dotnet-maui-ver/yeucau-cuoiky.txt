BÀI TẬP LỚN CUỐI KỲ – LẬP TRÌNH MOBILE
Phát triển tiếp đề tài giữa kỳ, bổ sung Push Notification (bắt buộc) và một trong ba phương án kỹ thuật: Socket.IO, SignalR hoặc kiến trúc MVVM.

1. Hình thức thực hiện
Giữ nguyên nhóm 2 sinh viên và đề tài đã chọn ở giữa kỳ. Muốn đổi đề tài phải được giảng viên đồng ý.
Ứng dụng cuối kỳ là phiên bản mở rộng của bài giữa kỳ: hoàn thiện chức năng cơ bản, kết nối backend thật và bổ sung các yêu cầu kỹ thuật ở mục 3.
Backend tùy chọn: Node.js (Express/Fastify) hoặc ASP.NET Core Web API; cơ sở dữ liệu tùy chọn.
Mã nguồn quản lý bằng Git; lịch sử commit phải thể hiện đóng góp của cả hai thành viên.
2. Yêu cầu nền tảng (bắt buộc)
Hoàn thiện đầy đủ chức năng cơ bản của đề tài theo bảng giữa kỳ.
Đăng nhập/đăng ký qua backend; lưu token và tự động đăng nhập lại.
Dữ liệu nghiệp vụ được CRUD qua REST API; xử lý trạng thái đang tải, lỗi mạng, danh sách rỗng.
Điều hướng bằng React Navigation; quản lý trạng thái toàn cục bằng Redux/Redux Toolkit hoặc Context API.
3. Yêu cầu kỹ thuật nâng cao
Quy định: mỗi nhóm bắt buộc thực hiện Phần A – Push Notification và chọn 1 trong 3 phương án của Phần B (B1 Socket.IO, B2 SignalR, B3 MVVM). Nhóm thực hiện thêm một phương án khác của Phần B được cộng tối đa +1,0 điểm (tổng không vượt quá 10).

Phần A – Push Notification (bắt buộc)
Công nghệ gợi ý: expo-notifications + Expo Push Service, hoặc Firebase Cloud Messaging (FCM).

Xin quyền nhận thông báo, lấy push token và gửi token lên server gắn với tài khoản người dùng.
Server tự động gửi thông báo khi xảy ra ít nhất 2 sự kiện nghiệp vụ khác nhau (không chấp nhận chỉ gửi thử bằng công cụ test).
Xử lý thông báo ở 3 trạng thái: foreground, background và đã tắt ứng dụng.
Nhấn vào thông báo thì điều hướng đến đúng màn hình liên quan (dựa vào trường data trong payload).
Có ít nhất 1 thông báo cục bộ được lên lịch (nhắc lịch, nhắc deadline…).
Có màn hình lịch sử thông báo (đã đọc/chưa đọc) hoặc tùy chọn bật/tắt từng loại thông báo.
Lưu ý: từ Expo SDK 53, Expo Go trên Android không hỗ trợ remote push notification; cần tạo development build và kiểm thử trên thiết bị thật.

Phần B – Chọn 1 trong 3 phương án
Phương án B1 – Giao tiếp thời gian thực bằng Socket.IO

Server Node.js + socket.io; client socket.io-client.

Xây dựng server Socket.IO; xác thực kết nối bằng token đăng nhập (middleware xác thực khi handshake).
Cài đặt ít nhất 2 sự kiện realtime hai chiều (emit/on) gắn với nghiệp vụ đề tài.
Sử dụng room để chỉ gửi dữ liệu đến đúng nhóm người dùng (theo lớp, đơn hàng, dự án…).
Giao diện cập nhật tức thời không cần tải lại; minh họa bằng 2 thiết bị/giả lập chạy song song.
Hiển thị trạng thái kết nối, tự động kết nối lại; hủy lắng nghe sự kiện khi rời màn hình hoặc đăng xuất.
Phương án B2 – Giao tiếp thời gian thực bằng SignalR

Server ASP.NET Core SignalR (Hub); client @microsoft/signalr.

Xây dựng Hub SignalR; xác thực kết nối bằng JWT (accessTokenFactory phía client, [Authorize] phía Hub).
Cài đặt ít nhất 2 phương thức realtime hai chiều (client gọi invoke lên Hub, server gọi Clients.* về client) gắn với nghiệp vụ đề tài.
Sử dụng Groups để chỉ gửi dữ liệu đến đúng nhóm người dùng.
Giao diện cập nhật tức thời không cần tải lại; minh họa bằng 2 thiết bị/giả lập chạy song song.
Hiển thị trạng thái kết nối, cấu hình withAutomaticReconnect; gỡ handler (off) và dừng kết nối khi rời màn hình hoặc đăng xuất.
Phương án B3 – Kiến trúc MVVM (Model – View – ViewModel)

ViewModel có thể cài đặt bằng custom hook (useXxxViewModel) hoặc class kết hợp MobX/Redux Toolkit.

Tách rõ 3 tầng:
Model: entity, Repository, Service (API, storage, notification).
ViewModel: state hiển thị, logic nghiệp vụ, kiểm tra dữ liệu, các hành động cho View.
View: chỉ hiển thị và gọi ViewModel; không gọi API, fetch, AsyncStorage trực tiếp.
Áp dụng MVVM cho toàn bộ ứng dụng, tối thiểu 3 màn hình chính.
Repository khai báo theo interface chung để thay được nguồn dữ liệu (API thật / mock) mà không sửa ViewModel.
Viết ít nhất 3 unit test cho ViewModel bằng Jest (dùng repository giả lập).
Báo cáo có sơ đồ kiến trúc MVVM và giải thích luồng dữ liệu cho 1 chức năng.
Cấu trúc thư mục tham khảo:

src/
├── models/          // Product.ts, Order.ts
├── services/        // apiClient.ts, notificationService.ts
├── repositories/    // ProductRepository.ts (interface + cài đặt API / mock)
├── viewmodels/      // useProductListViewModel.ts
├── views/
│   ├── screens/     // ProductListScreen.tsx
│   └── components/  // ProductCard.tsx
├── navigation/
└── __tests__/       // useProductListViewModel.test.ts
